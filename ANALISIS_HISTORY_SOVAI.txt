5) FLUJO CORRECTO RECOMENDADO (ENTORNO ACTUAL)
Paso 1: construir imagen
  docker build -t odoo-woocommerce-integrator .

Paso 2: levantar contenedor con compose
  docker compose up -d

Paso 3: validar salud
  curl http://localhost:8088/health
  curl http://localhost:8088/health/odoo
  curl http://localhost:8088/health/woocommerce

Paso 4: validar sincronizacion
  curl -X POST "http://localhost:8088/sync/products?limit=20"
  curl -X POST "http://localhost:8088/sync/orders?limit=50"

Paso 5: observar logs
  docker logs -f odoo-woocommerce-integrator

Cuando hay cambios de codigo:
  docker build -t odoo-woocommerce-integrator .
  docker compose up -d --force-recreate

6) RIESGOS DETECTADOS Y MITIGACIONES
Riesgo A: secretos expuestos en history (alto)
Mitigaciones:
- Rotar WEBHOOK_SECRET, WC_CONSUMER_SECRET y cualquier password/token expuesto.
- No pasar secretos en linea de comandos.
- Usar archivo .env y lectura por aplicacion.
- Configurar shell para no guardar comandos sensibles.

Riesgo B: errores tipograficos en comandos operativos (medio)
Mitigaciones:
- Definir runbook con comandos exactos.
- Crear scripts estandar (deploy, healthcheck, rollback).

Riesgo C: cambios manuales sobre volumenes/datos sin trazabilidad (alto)
Mitigaciones:
- Estandarizar restauraciones via script documentado.
- Registrar toda accion destructiva con ticket/bitacora.

Riesgo D: dependencia de pruebas manuales (medio)
Mitigaciones:
- Agregar smoke checks automatizados post-deploy.
- Agregar prueba automatica de endpoints clave.
